# project-evidence-contract / spine

1. Use the receipted evidence-contract template bytes already loaded with this spine; do not reload a contract file directly. Locate project; require `project.md` and `product-contract.md` at Build/Platform.
2. Read in parallel: product contract (promise/MM/AI behavior), context, architecture, active recipe evidence defaults, target platforms, and production distribution shape.
   Treat absent architecture, provider, CI, and distribution choices as open. Use substrate-neutral mechanisms and conditional future gates; never turn template examples into selected technology or claim that an uncommitted command is wired.
3. Enumerate every `PRM-NNN` into the Promise Proof Map. Each row preserves the promise claim and names an observable mechanism, admissible evidence, and a negative/failure probe that would make the row fail. No aggregate row may stand in for multiple promises.
4. For each target platform, run skeptical review over at least three materially different valid/invalid proof framings. Lock the one tied to the paid promise and runtime substrate; log the decision.
5. Name production-like proof per platform. Dev-server, mock-only, source inspection, and unadjudicated screenshots are invalid whenever they cannot observe the claim.
6. Enumerate each external service and interaction boundary that the project actually declares. State what proves real acceptance, persistence, authorization, billing, failure posture, and observability. Do not invent a service to make the table concrete.
7. Define persona LARP scope for UI products or integration/stress scenarios for backend products. Every magic moment and paid path gets a reachable proof mechanism.
8. Fill readiness criteria from NO-SHIP through SHIP. Every state names required artifacts and blockers; paid products require COMMERCIAL-RC.
9. Customize the standard adversarial probes without treating the probe list as done. Require negative controls and evidence storage paths.
10. Enforce boundaries: product-contract owns the promise; evidence-contract owns proof; AGENTS owns workspace process. Do not duplicate or contradict them.
11. Write `evidence-contract.md`. After its final edit, run `stamp-truth.sh` standalone, then its strict template validator standalone. Do not chain, pipe, wrap, or mutate afterward; each recorded exit must belong to that command.
Never allow one source to be both valid and invalid. Never permit a readiness claim without its criteria or a claim without an observable mechanism.
