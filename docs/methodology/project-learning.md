# Project learning

Speck separates immediate capture, validated project memory, and methodology feedback.

1. `speck-learn` captures an observation where it is discovered and applies any already-binding correction.
2. Story retrospective preserves the concrete occurrence without generalizing it.
3. Epic retrospective may validate recurrence across stories and promote a reusable, evidence-backed rule into the project's `.speck/patterns/learned/` when a future consumer exists.
4. Project retrospective reconciles patterns across epics and retires or broadens project-owned rules.
5. A defect in Speck itself routes to `speck-feedback` and Speck methodology development, never into a product's learned-pattern library.

Vanilla Speck ships no learned project patterns. CLI sync and upgrades preserve the project-owned directory without seeding or overwriting it.
